# ICMP correctness

Use cancellable .NET Ping, never external commands. Ping uses a monotonic scheduler, bounded channels and fixed workers; each target owns one work item and cannot overlap itself. DNS and ICMP have separate workers within a shared concurrency cap. Packet-rate tokens are consumed immediately before send. Skip missed deadlines instead of replaying them. Trace uses bounded rolling TTL discovery, then independent per-TTL polling with periodic/event-triggered full rediscovery. One request per TTL, with generation cleanup awaited before rediscovery; reverse DNS cannot block discovery. Fast TTLs do not await slow TTLs, missing replies do not invent route changes, and paused partial rounds cannot commit route comparisons. Each desktop trace session owns its engine; the actual shared ICMP adapter caps native concurrency at 128. Pause cancels outstanding requests, ignores cancelled attempts, awaits workers at the pause boundary; Resume keeps aggregates. Stop awaits every worker before restart. Only completed attempts count as Sent. Cached snapshots carry session/cycle/probe identifiers; internal scheduling/UI timings never replace network RTT.

CIDR excludes network/broadcast through /30; /31 includes both addresses and /32 includes one. First duplicate wins description and source metadata. DNS errors are Unknown with zero sent. Successful echo RTT uses PingReply.RoundtripTime; TTL-expired PingReply RTT is not reliable on Windows, so measure elapsed time around the actual TTL echo request instead, and disclose this definition. No response means no RTT. Route changes compare responding address sets at the same TTL across completed cycles; missing responses are unknown and cannot change the baseline. Jitter is mean absolute delta of consecutive valid RTTs.
