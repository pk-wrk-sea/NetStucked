# WPF and MVVM

Core never references WPF. Desktop view models use CommunityToolkit commands and observable properties. Only the visible page runs a 33ms DispatcherTimer; revision deltas coalesce by target/hop and row application uses a cooperative 4ms budget. Notify only changed cell properties; sort refresh is necessary only if actual sort keys change. Sort/filter refresh is throttled to 500ms during monitoring and deferred while Description editing is active. Append history/event changes without resetting the entire collection. No network work runs on the Dispatcher. Page views and view models survive navigation; their network engines continue when hidden, and closing the window stops and awaits Ping and every trace session. Grids virtualize rows and columns. Save visibility/order/width by stable binding names, not header display strings. Dense tables may scroll horizontally at narrow widths; do not shrink fonts to conceal clipping.

Shutdown also awaits Port and shared WAN metadata/update work. Current theme resources apply Light/Dark/System to application popups; native trust/file dialogs remain Windows-managed. Panel transitions/resizing are view behavior, not network scheduling. The selected milestone/approval register governs future Views/VMs; later authorized defect documents govern caret/toolbar/caption changes.

Approved Wi-Fi adds a cached NetworkInfoViewModel/View and a coalesced background context observer. Native WLAN/EAP/credential APIs stay in Infrastructure; the Dispatcher applies bounded snapshots only. Explicit mutations are serialized, readiness/tests cancel and drain, and shutdown/update preparation await Wi-Fi work. Preserve missing/permission-limited observations and actual source/interface attribution; never seed company profiles or expose secret fields in JSON/logs/exports. See docs/WIFI_PROFILE_MANAGER.md.
