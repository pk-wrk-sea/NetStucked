# Architecture

Dependency arrows: Desktop → Core; Desktop → Infrastructure → Core. Core is `net10.0`, free of WPF. Desktop is `net10.0-windows` with WPF. Infrastructure uses built-in .NET APIs and is portable for adapter tests; production networking is validated on Windows.

Core holds parser/CIDR math, cached immutable snapshots, bounded statistics and the async session controller. MultiTargetPingService uses a monotonic priority scheduler and separate bounded DNS/ICMP/completion channels. Each target owns one work item across these stages, so it cannot overlap itself. Fixed worker counts, a shared network semaphore and a packet token bucket cap admission. When hostnames are present, DNS workers reserve a small portion of the concurrency budget so DNS and ICMP can both progress. Each TracerouteMonitoringService owns rolling discovery, independent per-TTL polling loops and periodic/event-triggered rediscovery. Responding sets are compared only when all known hops have completed new evidence; no same-TTL request overlaps itself. The workspace owns up to eight independently cancellable engines. DNS runs separately from hop discovery. Both use cancellable operation leases; pause drains leases, stop awaits all tasks.

Infrastructure adapts .NET Ping/Dns and local JSON/text persistence. Desktop uses CommunityToolkit observable models/commands, DI and Microsoft.Extensions.Logging. The visible page reads revision deltas every 33ms, coalesces them by target/hop and applies rows with a cooperative 4ms budget. Changed cells notify individually. Sorting/filtering refreshes only when keys/membership change, at most every 500ms during monitoring; explicit filter changes/export refresh immediately, except while a Trace Description edit is active. History/event collections update incrementally. Hidden page timers stop while their engines continue. The UI never performs network calls. Page ViewModels live for the window lifetime; shutdown asynchronously stops Ping and all trace sessions before disposing DI/logging.

Session, cycle and probe identifiers distinguish completed samples across restarts. Internal diagnostics retain at most 256 recent timing observations per metric, with lifetime counts/mean/max and a recent-sample p95. Scheduler delay, queue wait, DNS time, API duration and publish-to-UI delay are separate from the actual RTT columns. Diagnostics are logged on Stop/shutdown without adding a monitoring page.

Column layout attached behavior and dialogs are view concerns. They do not probe. CSV files use a native save dialog. Named address templates and destination history are bounded local preferences, written immediately through serialized atomic replacement. The real shared ICMP adapter limits total outstanding native requests to 128. Native monitor-work-area handling, resize guide, Fit Columns and scroll anchoring stay in view behaviors. No speculative repository/service frameworks or database are required.
