# Architecture — current 0.4.0 and proposed module boundaries

Current production structure: three projects (`NetStucked.Core`, `NetStucked.Infrastructure`, `NetStucked.Desktop`) plus deterministic/integration tests and the Windows QA harness. The descriptions below distinguish existing implementation from future proposed contracts. Planning documentation adds no production dependency.

Dependency arrows: Desktop → Core; Desktop → Infrastructure → Core. Core is `net10.0`, free of WPF. Desktop is `net10.0-windows` with WPF. Infrastructure uses built-in .NET APIs and is portable for adapter tests; production networking is validated on Windows.

Core holds parser/CIDR math, cached immutable snapshots, bounded statistics and the async session controller. MultiTargetPingService uses a monotonic priority scheduler and separate bounded DNS/ICMP/completion channels. Each target owns one work item across these stages, so it cannot overlap itself. Fixed worker counts, a shared network semaphore and a packet token bucket cap admission. When hostnames are present, DNS workers reserve a small portion of the concurrency budget so DNS and ICMP can both progress. Each TracerouteMonitoringService owns rolling discovery, independent per-TTL polling loops and periodic/event-triggered rediscovery. Responding sets are compared only when all known hops have completed new evidence; no same-TTL request overlaps itself. The workspace owns up to five independently cancellable engines with one protected main session under the 0.4.0 revision. DNS runs separately from hop discovery; the compact desktop normalizes optional reverse DNS off. Both use cancellable operation leases; pause drains leases, stop awaits all tasks. IPv6 is supported for individual Ping targets; Traceroute is IPv4 ICMP only.

Infrastructure adapts .NET Ping/Dns, TCP/UDP sockets and local JSON/text persistence. MultiTargetPortService schedules independent endpoint checks with bounded DNS/work queues and single-pass/continuous operation. PortScanPlanner previews explicit Host/IP/CIDR × protocol/ports: up to 1,024 hosts, 64 ports, 16,384 checks; >4,096 needs renewed scope acknowledgement. Thirty-two concurrent operations and 128 send admissions/second bound port work. Generic UDP silence is inconclusive and has no fabricated RTT. Desktop uses CommunityToolkit observable models/commands, DI and Microsoft.Extensions.Logging. The visible page reads revision deltas every 33ms, coalesces them by target/hop and applies rows with a cooperative 4ms budget. Changed cells notify individually. Sorting/filtering refreshes only when keys/membership change, at most every 500ms during monitoring; explicit filter changes/export refresh immediately, except while a Trace Description edit is active. History/event collections update incrementally. Hidden page timers stop while their engines continue. The UI never performs network calls. Page ViewModels live for the window lifetime; shutdown asynchronously stops Ping, Port, all trace sessions and metadata/update work before disposing DI/logging.

Session, cycle and probe identifiers distinguish completed samples across restarts. Internal diagnostics retain at most 256 recent timing observations per metric, with lifetime counts/mean/max and a recent-sample p95. Scheduler delay, queue wait, DNS time, API duration and publish-to-UI delay are separate from the actual RTT columns. Diagnostics are logged on Stop/shutdown without adding a monitoring page.

Column layout attached behavior and dialogs are view concerns. They do not probe. CSV files use a native save dialog. Named address templates and destination history are bounded local preferences, written immediately through serialized atomic replacement. The real shared ICMP adapter limits total outstanding native requests to 128. Native monitor-work-area handling, resize guide, Fit Columns and scroll anchoring stay in view behaviors. No speculative repository/service frameworks or database are required.

## Existing shared descriptions, appearance and update flow

HopDescriptionService merges manual mappings across sessions with optional eligible-public-IP RIPEstat organization/ASN metadata. Infrastructure performs bounded HTTP work; private/reserved addresses are excluded, manual mappings take priority and cache/pending-work limits are enforced. This metadata is not router-manufacturer or network-response evidence. ThemeService and shared WPF resources apply approved Light/Dark/System themes; view behaviors own panel transitions/resizing and current brand assets remain supplied resources.

Core Releases/Updates model SemVer, eligible package identity and orchestration contracts. Infrastructure implements public fixed-project GitHub metadata, streamed/hash-verified installer preparation, native Windows trust/version/path validation, exact compatible settings backups and UpdateRunner. Desktop Updates VM shows real selection/notes/progress/acknowledgement; App has isolated `--apply-update` helper mode. Diagnostics and WAN lookups drain before handoff; the helper waits for its real parent, revalidates, backs up schema-1 settings, requests Setup elevation, verifies version and restarts using the original user token. No background installation or database schema compatibility is assumed. Actual machine acceptance is still pending.

## Proposed persistent and network modules — not implemented

Read [FEATURE_DEPENDENCIES](FEATURE_DEPENDENCIES.md) and the selected [milestone](MILESTONE_INDEX.md) before adding contracts. Future SQLite should sit behind UI-free history/incident/asset/evidence interfaces, with migrations, one bounded writer, paged reads, retention and tested backup/downgrade compatibility. Current schema-1 JSON preferences remain separate unless an approved migration says otherwise.

Network Info/WLAN belongs behind Windows adapters; diagnostics/monitoring compose existing probes through bounded Core coordinators. Shared SSH transport supports both a real terminal emulator and a separate read-only Collector. Collector persists raw command evidence, parsers produce versioned traceable facts, Inventory reconciles human/observed records, and Topology/CVE consume fact interfaces. Upgrade Planner consumes reviewed assessments, never performs device upgrades in the proposed scope. These consumers remain decoupled; avoid one giant service/ViewModel or circular ownership.

The future central collector is a separate service/process with explicit deployment/auth policy, not a timer added to WPF. Commercial licensing/payment contracts remain On Hold; no dependencies or runtime checks are introduced. Approval and actual verification remain distinct from architectural proposals.
