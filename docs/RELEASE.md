# Release 0.2.0

0.2.0 and the separate 0.2.1 TEST BUILD were published with human authorization on 2026-10-09. Both have installers compiled and verified on GitHub Actions. See [the publication report](GITHUB_RELEASE_REPORT_2026-10-09.md) for immutable tags, package hashes, CI evidence and remaining manual-install limitations. 0.2.0 remains GitHub Latest; the 0.2.1 test release exercises the manual checker shipped in 0.2.0.

Run restore/build/tests first, then `pwsh -File scripts/Publish.ps1`. Output: `artifacts/publish/win-x64/NetStucked.exe`, full self-contained directory. Use `-PublishDirectory artifacts/port-test/0.2.0/final/publish` for a separate 0.2.0 package. With Inno Setup 6 installed, run `pwsh -File scripts/Publish.ps1 -CompileInstaller`; output `artifacts/installer/NetStucked-0.2.0-win-x64-setup.exe`. To compile manually, pass `/DMyAppVersion=0.2.0` and `/DPublishDir=<absolute publish directory>` to ISCC on `installer/NetStucked.iss`. Without a supplied version define the .iss intentionally fails to prevent divergent metadata.

Installer uses stable AppId `{82CA4B18-541C-4D04-9A09-E676AB21F504}`, Program Files x64, optional desktop shortcut, Start Menu entry and full publish contents. Per-user settings/logs are outside Program Files; uninstall deliberately retains them. A downgrade is manual: stop the app, back up `%LOCALAPPDATA%\NetStucked`, uninstall newer build, install trusted prior signed release and restore compatible settings. No automatic download, update or rollback exists.

Updates & Recovery now reads public stable SemVer releases from `pk-wrk-sea/NetStucked` on demand and opens only that project's release pages. A manually downloadable installer uses the filename `NetStucked-{version}-win-x64-setup.exe`. Development version history comes from `src/NetStucked.Desktop/Resources/ReleaseHistory.json`; maintain its actual changes alongside CHANGELOG and the central version. No credentials, automatic checking/downloading/installing or rollback executor are present. Additive schema 1 retains previous Ping/Trace settings; always preserve a compatible preferences backup before a manual downgrade. Empty/failed release checks never manufacture available updates.

Before production rollout, test clean Windows 10/11 install/uninstall/upgrade, publisher trust, version metadata, artifact hash/size and retained settings. The [local development QA report](QA_0.2.0.md) predates publication; the [publication report](GITHUB_RELEASE_REPORT_2026-10-09.md) records the later installer builds. These installers are unsigned. Installer compilation and application startup checks do not prove a successful installer upgrade or settings recovery.

## Verified-package installer workflow

Prepare an authorized version commit/tag and draft release, then attach the exact tested `NetStucked-{version}-win-x64-portable.zip`, its SHA-256 file and package manifest. Dispatch `.github/workflows/release.yml` from `main` with the existing tag and ZIP hash. It checks the tag against the central version and draft, builds/tests the tagged source, verifies the downloaded package, exercises its exact application DLLs and self-contained executable, and uses the Windows runner's Inno Setup compiler to package those same bytes. It attaches the installer, hash and `installer-build.json` to the draft. It never replaces published assets or publishes a release itself. Inspect CI results and hashes before explicitly publishing the draft.

Keep published tags/packages immutable. `.gitattributes` disables text normalization to preserve the canonical scope/reference bytes and exact source input. SDK-generated executable ProductVersion may include `+<Git SHA>`; the installer workflow verifies its SemVer portion. Application update checks use SemVer without that build suffix. Preserve the stable installer AppId across versions.

For update/recovery testing, use 0.2.0 to discover the clearly labeled 0.2.1 test release. Install it manually or extract its portable package into a separate folder. The 0.2.1 recovery guide identifies documented 0.2.0; stop sessions, close the application and back up per-user settings before any manual uninstall/downgrade. Do not run diagnostics from both builds against the same target accidentally. No automatic updater or rollback executor is implemented.
