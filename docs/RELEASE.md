# Release 0.2.0

Run restore/build/tests first, then `pwsh -File scripts/Publish.ps1`. Output: `artifacts/publish/win-x64/NetStucked.exe`, full self-contained directory. Use `-PublishDirectory artifacts/port-test/0.2.0/final/publish` for a separate 0.2.0 package. With Inno Setup 6 installed, run `pwsh -File scripts/Publish.ps1 -CompileInstaller`; output `artifacts/installer/NetStucked-0.2.0-win-x64-setup.exe`. To compile manually, pass `/DMyAppVersion=0.2.0` and `/DPublishDir=<absolute publish directory>` to ISCC on `installer/NetStucked.iss`. Without a supplied version define the .iss intentionally fails to prevent divergent metadata.

Installer uses stable AppId `{82CA4B18-541C-4D04-9A09-E676AB21F504}`, Program Files x64, optional desktop shortcut, Start Menu entry and full publish contents. Per-user settings/logs are outside Program Files; uninstall deliberately retains them. A downgrade is manual: stop the app, back up `%LOCALAPPDATA%\NetStucked`, uninstall newer build, install trusted prior signed release and restore compatible settings. No automatic download, update or rollback exists.

Updates & Recovery now reads public stable SemVer releases from `pk-wrk-sea/NetStucked` on demand and opens only that project's release pages. A manually downloadable installer uses the filename `NetStucked-{version}-win-x64-setup.exe`. Development version history comes from `src/NetStucked.Desktop/Resources/ReleaseHistory.json`; maintain its actual changes alongside CHANGELOG and the central version. No credentials, automatic checking/downloading/installing or rollback executor are present. Additive schema 1 retains previous Ping/Trace settings; always preserve a compatible preferences backup before a manual downgrade. Empty/failed release checks never manufacture available updates.

Before distribution, test clean Windows 10/11 install/uninstall/upgrade, verify publisher signature, version metadata, artifact hash/size and retained settings. Tag v0.2.0 and manually attach installer/hash/release notes to GitHub Releases only when authorized. The [current QA report](QA_0.2.0.md) distinguishes build validation from those unperformed release gates. The portable 0.2.0 ZIP is built locally; no installer EXE, tag, commit, push or GitHub release is published by this task.
