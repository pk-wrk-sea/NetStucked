## Historical 0.3.0 foundation

0.3.0 implements user-triggered installation/recovery of the selected public GitHub build. The later 2026-10-09 request authorizes publishing it with a 0.3.1 TEST BUILD and retiring 0.2.x release/build downloads while preserving Git history/tags and local verified backups. See [actual publication status](GITHUB_RELEASE_0.3_REPORT_2026-10-09.md), [behavior and failure recovery](FEATURES_0.3.0.md) and [original local QA](QA_0.3.0.md). No background updater is present.

Restore/build/test first, then run `pwsh -File scripts/Publish.ps1`. The central SemVer in `Directory.Build.props` supplies application and installer versions. Self-contained output is `artifacts/publish/win-x64/NetStucked.exe`. For this local package use `-PublishDirectory artifacts/selected-build/0.3.0/final/publish`. With Inno Setup 6, add `-CompileInstaller -Iscc <compiler path>`; output is `artifacts/installer/NetStucked-0.3.0-win-x64-setup.exe`. Manual compilation requires `/DMyAppVersion=0.3.0` and `/DPublishDir=<absolute directory>`; an absent version define intentionally fails.

Keep stable AppId `{82CA4B18-541C-4D04-9A09-E676AB21F504}`, x64 Program Files, full private runtime payload, Start Menu and optional desktop shortcut. Per-user settings/logs live outside Program Files and are retained after uninstall. In-place downgrade uses the same AppId and installer `ignoreversion` files; verify this on clean Windows before release acceptance. The helper prevents forced closing/restart of other applications and waits for Setup. Existing unsigned installers require acknowledgement; Windows UAC/SmartScreen are preserved. A failed installer is not a transactional restoration of Program Files.

Eligible release assets require the exact `NetStucked-{version}-win-x64-setup.exe` name, uploaded state, positive ID/size, GitHub SHA-256 digest and fixed-project HTTPS URL. Publish real metadata/assets; never fabricate a version or digest to enable an action. Source, CHANGELOG and bundled `ReleaseHistory.json` must describe actual changes. Schema-1 settings are backed up with exact bytes and verified before restoration. Inspect actual logs/results after installation, including restart-required conditions.

## Verified-package installer workflow

Prepare a human-authorized version commit/tag and draft release, then attach the exact tested portable ZIP, SHA-256 file and package manifest. Dispatch `.github/workflows/release.yml` from `main` with that existing tag and ZIP hash. It verifies tag/version/draft, tests tagged source, verifies the package, exercises exact application DLLs and executable, and compiles those bytes on the Windows runner. It attaches the installer/hash/`installer-build.json` to the draft without replacing published assets or publishing automatically. Inspect CI and hashes before explicit publication.

Keep published tags/packages immutable. `.gitattributes` disables normalization to preserve canonical references and exact input bytes. ProductVersion can include `+<Git SHA>`; compare its SemVer portion, not that suffix, with the central version. Maintain publisher signing separately; package hashes do not replace Authenticode trust. Test clean Windows 10/11 install, upgrade, downgrade, uninstall, UAC cancellation, partially failed Setup, restart-required conditions, settings compatibility and signature/reputation before production acceptance.
