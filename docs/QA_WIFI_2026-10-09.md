## Important interpretation

WLAN mutations call Native Windows APIs, but their actual hardware/authentication behavior is unverified in this environment. Connect requires matching Windows completion/state; a command accepted by Windows is not reported as successful by itself. Already-connected profiles are verified without reconnecting. Native pending requests are cancelled/drained on timeout/cancel; real driver/connection failure combinations still need lab acceptance.

Gateway probes select the actual adapter's source address; Windows ICMP does not expose the physical egress interface, and the result discloses this. DNS/TCP/HTTP sockets bind source address and outgoing interface; real multi-adapter/VPN/weak-host routes need lab confirmation. HTTP checks expected status/headers and retain TLS validation; a 200 response alone does not prove application functionality or absence of a captive portal. HTTP uses direct connections without a proxy.

Histories retain 500 events/100 test runs; no request reply spam. JSON schema stays 1 and old settings load with defaults. Older releases can ignore new fields and drop them when saving; do not claim full metadata retention on downgrade. Windows-owned profiles/credentials stay outside JSON. Current recovery backups remain the compatibility mechanism; real installed-version rollback with Wi-Fi fields is NOT TESTED.

M01 is partially implemented: this approved Wi-Fi slice is built/tested locally, while wider route/neighbor facts and hardware acceptance remain open. Expanded A09 EAP editors/certificate provisioning, Dashboard and unrelated planned pages remain excluded.
