# 0.11.2 - Config Collector SSH compatibility

The human reports an actual installed 0.11.1 Collector failure on 2026-10-21, with Detail `SSH negotiation/session failed; no credential fallback.` Cisco syslog includes a successful AES256-CTR/SHA512-ETM session and a later failed session. The successful event cannot be attributed to the installed Tmds 0.26 client: that provider supports AES-GCM/ChaCha20 only. A fixture restricted to the reported strong algorithm pair reproduces the exact error before any authentication. The device's complete offered algorithms and actual-device resolution remain unverified.

This patch is an authorized correction to the existing explicit-start Collector; standing distributable publication intent remains. Terminal keeps its existing provider and trust workflow. No working-network probes, device changes, algorithm weakening, secret persistence or automatic provider/credential retry is added.

## Implementation contract

Provider references: [Tmds 0.26 supported/default algorithms at its pinned source](https://github.com/tmds/Tmds.Ssh/blob/fb33d6c20f1f320ad0211713825074cf85297b50/src/Tmds.Ssh/SshClientSettings.Defaults.cs), [SSH.NET 2026.0.0 tagged source](https://github.com/sshnet/SSH.NET/tree/7b2fd3dbf2c86a80a7b06cea020aa5f821c9902e). The latter's MIT license is included under Resources/ThirdParty; dependent package licenses remain those of their respective providers.

- Collector-only SSH.NET 2026.0.0 adapter, pinned package/source and bundled MIT license. Explicit modern encryption/KEX/MAC/host-key allowlists include AES-CTR with SHA-2 ETM while excluding SHA-1 signatures/MAC/KEX, CBC, 3DES, DSA and group1.
- Verify the original target's pinned SHA-256 host key before any SSH authentication, including none/password probes, and on rekey. Unknown/changed keys fail closed. Authentication fallback requires an observed password-authentication rejection; unsupported/MFA/partial/password-change, setup errors and cancellation never trigger AUTH2.
- Owned per-attempt loopback SOCKS5 bridge with a memory-only random nonce, exact authorized destination and bounded bidirectional buffers. It changes no system proxy, firewall or device settings and exposes no remote listener. Socket ownership permits cancellation during provider KEX/none-auth/password/shell waits; close sockets and await all setup/stream/relay tasks. No raw bridge traffic or nonce is logged.
- Run connect/open away from Dispatcher. Give shell setup a fresh configured deadline after authentication. Subscribe to the public Session data events before creating its single shell channel, bind the confirmed local channel number and enqueue into bounded streams before the SDK receives a duplicate. Cap combined pre-ready stdout/stderr at 64 KiB; larger initial output fails explicitly. Serialize the initial and per-event drain of the SDK's duplicate ShellStream buffer. Do not use the SDK Shell input worker. Preserve separate incremental stdout/stderr UTF-8 decoding and downstream streamed evidence/redaction; track writes and join them before disposal.
- Send CR for SSH terminal commands; keep Telnet's existing LF-to-NVT-CRLF encoding. Test exact wire framing, fragmented/coalesced CR/CRLF and no duplicate commands.
- Present static, safe stage-specific errors. Do not expose arbitrary provider exceptions, banners, usernames/passwords or configurations through error text. Keep existing capture schema, command provenance, partial preservation and no replay after a command is sent.

The combined application output queue is 32 x 4 KiB plus bounded decoder/pending state; this is not a 256 KiB total-process or SSH receive-window claim. SDK packets and its temporary pre-ready duplicate buffer have separate finite bounds. No compression is negotiated. A server accepting none-auth without running the explicit password method is rejected because this adapter has not established its owned Session hooks.

Implementation and owned regression verification are tracked in [QA_0.11.2.md](QA_0.11.2.md); [immutable source/assets/CI/public updater evidence](GITHUB_RELEASE_0.11.2_REPORT_2026-10-21.md) confirms publication as GitHub Latest. Physical Cisco/AAA policy/command support and real-device acceptance remain open until the corrected build is exercised on the intended device.
