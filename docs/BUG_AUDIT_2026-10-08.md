# NetStucked 0.1.0 bug audit — 2026-10-08

Windows 10 x64, .NET SDK 10.0.401. Tested source and isolated WPF windows; all actual network traffic in this audit was loopback. The existing user application (portable build, PID 13436 when inspected) was left running and its directory/preferences were not modified.

## Confirmed bugs and corrections

| Bug | Impact / reproduction before correction | Correction and regression coverage |
|---|---|---|
| High: Trace refresh during Description editing | Begin a real DataGrid Description edit while tracing; the next changed snapshot calls `CollectionView.Refresh()`. Reproduced `InvalidOperationException: 'Refresh' is not allowed during an AddNew or EditItem transaction.` An unhandled Dispatcher timer exception can terminate the app. | Continue updating row properties; defer collection sorting/filtering until editing ends. WPF harness holds the edit across another real trace cycle, changes the filter, commits and verifies the pending filter applies. |
| Medium: horizontal scrolling reversed | Shared template set `IsDirectionReversed=True` and PageUp/PageDown for horizontal bars too. The original template failed the direction regression. | Horizontal track now increases left-to-right and uses PageLeft/PageRight. Verified the real WPF Track maps a rightward distance to a positive value, with the correct repeat-button commands. Vertical behavior/6px dimensions are retained. |
| Medium: nullable JSON settings reached the UI | `TargetText:null`, `TraceTarget:null`, null column-list entries and null descriptions were accepted as loaded settings. Null targets/columns can reach `.Trim()` or column layout enumeration and fail startup. Four new input cases failed the expected rejection before correction. | Validate nullable strings and nested collections before accepting preferences; invalid files use defaults and expose LoadError. All four regression cases pass. |
| Medium: final-hop probe count ignored | With `ProbesPerHop=3`, intermediate TTL got three attempts, but the destination/terminal TTL got only one. Adapter reproduction expected TTL sequence `1,1,1,2,2,2` and received `1,1,1,2`. | Finish all configured attempts at the final TTL, then end the path. Success and terminal-unreachable adapter cases pass; actual loopback trace verifies six replies over two three-probe cycles. |
| Medium: immediate Trace CSV exported an old Description | Change Description and export before the next 250ms snapshot update. CSV used cached `row.Data.Description`. The WPF export regression failed even though the editable row already showed the new text. | Export the current editable Description alongside the visible measured snapshot. Immediate export during editing now includes the latest Thai/English text. |

Changes are in `TracerouteViewModel.cs`, `Theme.xaml`, `UserSettingsStore.cs` and `TracerouteMonitoringService.cs`. Regression coverage is in `SettingsTests.cs`, `TraceServiceTests.cs` and `NetStucked.WindowsQa/Program.cs`. Version remains development version 0.1.0; no release was published.

## Explicitly untested in this follow-up

No authorized remote multi-hop destination was supplied; intermediate replies, timeouts, route changes and terminal-unreachable behavior are covered by deterministic adapters, not claimed as observed remote traffic. Native file/settings dialogs, physical mouse/keyboard/screen-reader interaction, real monitor DPI transitions, Windows 11 and installer compilation/install/uninstall/upgrade were not tested. Scaled WPF bitmaps do not constitute a physical multi-monitor test.

The final published DLLs were exercised through a real isolated WPF harness using the installed .NET 10 runtime. The corrected EXE's own startup/WM_CLOSE path and its bundled runtime were not launched again, because the current smoke script shares the user's active preferences path. The earlier published EXE startup/close result in QA_REPORT.md applies to the earlier build only.
