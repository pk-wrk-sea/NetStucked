## TCP Port Test

- One endpoint per line: `host:port description` or `host port description`. IPv6 accepts `[::1]:443 description` or `::1 443 description`. Hosts/IPs use the existing validation rules; descriptions support Unicode. Duplicates are identified by normalized host and port, keeping the first description. Ports are 1–65535. CIDR/ranges, URLs, UDP and bulk port scanning are not accepted.
- Maximum 1024 endpoints, 1 MB input, 10000 lines and 512 characters per description. Named templates are stored locally, separately from Ping templates; deletion asks Yes/No. At most 100 templates, names 1–80 characters. Application persistence stays in additive schema 1.
- Start, Pause/Resume, Stop; independent per-endpoint deadlines, exactly one work item per logical endpoint across scheduling, DNS and TCP queues. Cancellation is awaited before pause, stop and restart. Missed intervals are skipped, never accumulated into bursts.
- Cancellable .NET 10 `Socket.ConnectAsync` with a new IPv4/IPv6 socket for each test; no application payload, credential or shell utility. IPv4 is preferred for a hostname with both address families; the resolved address is displayed. This tests that one resolved address, without guessing other DNS answers.
- Only Interval (250–60000 ms) and Timeout (500–10000 ms) appear in Probe Settings. Defaults 1000/2000 ms. DNS has its own cancellable 3-second deadline, 30-second cache and 5-second retry backoff. DNS workers are isolated from TCP workers with reserved capacity; a slow lookup cannot occupy every TCP slot.
- Internal limits: 32 concurrent network operations, four DNS workers, 128 connection starts/second and bounded initial burst. Requested cadence is best effort under these limits and when a connect takes longer than its interval. Fast large lists can encounter OS ephemeral-port/TIME_WAIT pressure; actual socket errors remain visible. These limits do not change measurements.
- Outcomes: Connected, Refused, Timeout, DNS error, Unreachable, Error, Unknown (no completed observation yet). Refused comes only from the OS ConnectionRefused error. A closed port can show Timeout if Windows has not returned refusal within the chosen deadline. Successful TCP handshakes do not establish application/TLS health.
- Connect (ms), average/min/max use only measured successful handshake times, excluding DNS and queue wait. Failed attempts show no connect time. Failure % counts completed TCP attempts only; DNS errors contribute to the failed-endpoint count/history but are not fabricated TCP attempts. Cancellation contributes to neither attempts nor failures.
- Realtime sortable/filterable configurable results, Fit Columns, resize guides, one-second button hints, selected-endpoint history with stable scrolling and blank-space deselection, CSV with formula-safe text. History retention is capped at 500 samples per endpoint and 100000 across a session. History displays 100/500 latest samples. No charts or simulated telemetry.
- Cached WPF view, 33-ms background UI timer, latest-row coalescing, 4-ms frame application budget and deferred dynamic sort/filter refresh. Leaving the page stops presentation work while networking continues. Sidebar activity reflects the actual session state.

## Updates & Recovery

- Current version comes from compiled central version metadata in `Directory.Build.props`. The new feature release is **0.2.0**. Version History embeds the real 0.1.0 and 0.2.0 development changes; it does not claim those builds were published or installed previously.
- Check for Updates performs a user-triggered HTTPS public read of `pk-wrk-sea/NetStucked` Releases. No GitHub token or credential is read. Stable strict SemVer tags (optional `v` prefix) are compared to the current version; drafts/prereleases/foreign URLs are excluded. The API request considers the latest 100 release records and caps the response at 2 MB, nesting at 32, notes at 12000 characters and the complete request/read at 15 seconds.
- Remote release notes are displayed as plain text. Available-version/installer actions are enabled only for an actual newer listed release; an installer asset named `NetStucked-{version}-win-x64-setup.exe` changes the button to Download installer. Both actions open the verified project release page for manual review/download, without executing or downloading a file inside NetStucked.
- Empty results explicitly show that no stable SemVer release is published. API/access/rate-limit/timeout/format errors show a failed check and clear stale available-version actions. No failure is labeled up to date. Closing cancels and awaits a pending HTTP request.
- Version Recovery shows an earlier documented version and opens an inline manual backup/uninstall/install/settings-compatibility guide plus the project Releases page. No installed-version history, backup or automatic rollback is fabricated. The automatic-check switch is off/unavailable, matching the agreed manual workflow.
- Dashboard and Network Info stay placeholders. The original two approved PNGs and scope document remain unchanged.
