# 0.10.1 - Interactive Terminal host keys

Human follow-up on 2026-10-19: "host finger print เอามาทำไม เอาให้มันเหมือน secureCRT เลย". The named change is Terminal host-key interaction, in NetStucked's own theme. The earlier instruction to publish completed changes as distributable GitHub updates remains in effect. Original approved references and prior releases are immutable.

Remove the manual fingerprint field. Connect performs real SSH key exchange, then a first-use dialog offers **Accept Once**, **Accept & Save** and **Cancel** before authentication. Accept Once applies only to that handshake. Save persists the public identity for normalized host and port; future matching connections need no prompt. A changed key shows old and new SHA-256 fingerprints and requires an explicit verification checkbox before Accept Once or Replace & Save. Cancel/Escape/closing the dialog rejects; Cancel is the default button. Nothing accepts a key silently on first use or on change.

The interaction follows the documented [SecureCRT host-key workflow](https://www.vandyke.com/solutions/host_keys/index.html) and [saved-key management](https://www.vandyke.com/support/tips/009.html); this is not a clone of the full SecureCRT product or its assets. Terminal retains real offline emulation, five tabs and memory-only password/OpenSSH-key credentials from 0.10.0. Serial/SFTP/splits/recording remain outside the slice. Config Collector still uses its existing explicit pin policy.

**Host keys…** opens a themed, resizable saved-key table: endpoint, algorithm, SHA-256 and acceptance time. Remove requires confirmation and affects subsequent connections. Current sessions stay open. Nonsecret metadata lives in schema-1 `terminal-known-hosts.json`, at most 1000 hosts / 2 MiB, with serialized atomic writes and stale-write/removal checks. Corrupt/unreadable storage stops the connection before authentication; it is never silently treated as an empty trust database. No passwords, passphrases or private keys enter this file.

Legacy schema-1 connection profiles and their old HostPin property remain readable and round-trippable. The new UI's separate known-host database is authoritative: legacy pins do not auto-approve a first-use prompt or resurrect removed trust. Existing profiles therefore need one acceptance in the new flow. Older builds ignore the new known-host file and retain their original manual-pin behavior; this is not full installed downgrade acceptance.

The SSH library's connect timer is suspended only during host-key review; human review may exceed 15 seconds. Caller cancellation/Exit/update still cancels and closes the dialog. A separate 15-second bound remains for shell opening. Password authentication sends one attempt, no fallback/auto reconnect; algorithms are not weakened. Host prompts are serialized and the store is rechecked before a queued prompt or save. A changed stored key during approval rejects the stale save.

Implementation: Core owns host-key records/decisions/contracts; Infrastructure owns the bounded store, trust policy and SSH handshake callback; Desktop owns themed dialogs, management commands and dispatcher/cancellation handling. Deterministic and actual SSH tests use only owned fixtures.
